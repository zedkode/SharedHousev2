# Platform Administrator Guide

## 1. Purpose

This guide applies only to authorised staff operating the SharedHouse service. Platform access is production-sensitive and monitored. Household owners use the separate household guide.

## 2. Sign-in and session safety

Use your named account and required MFA. Never share accounts. Confirm the environment banner before acting. Re-authenticate for high-impact actions and end sessions on unmanaged devices.

## 3. Least-privilege workflow

Open a ticket/case, identify the exact task, use the narrowest permission, record reason and avoid household content. If private content is essential, use the approved time-limited escalation and view only required records.

## 4. Commerce operations

Use **Store transactions** to locate verified provider evidence and **Entitlements** to see calculated access. Trigger reconciliation when events are delayed. A support grant is temporary, named and audited; never edit provider transaction facts.

## 5. Support operations

Use exact account/household IDs when possible. Revoke compromised sessions, assist with verification, inspect safe sync/job metadata and document resolution. Do not take sides in normal roommate disputes or manually rewrite the household ledger.

## 6. Privacy operations

Track export/deletion deadline, identity verification, owner-transfer dependency, vendor propagation and completion evidence. Apply retention exceptions only with authorised basis. Never download export packages to unmanaged local storage.

## 7. Security operations

Investigate sign-in anomalies, token reuse, invitation abuse, malicious uploads and admin-access events. Preserve evidence and follow incident escalation. Do not disclose sensitive detection logic in routine support messages.

## 8. Jobs and provider events

Review failure reason and correlation chain before replay. Replays must be idempotent. Escalate repeated signature failures, provider-state mismatches, ledger-integrity alerts or privacy-job deadline risk.

## 9. Auditing

Every privileged change requires an accurate reason. Audit records are immutable. Attempts to evade auditing are security incidents.

## 10. Prohibited actions

- Browsing households without a case and authorised purpose.
- Asking for user passwords, recovery codes or full payment credentials.
- Granting permanent paid access from screenshots.
- Deleting or altering audit/ledger history.
- Exporting broad production datasets for convenience.
- Using production data in development or demonstrations.
